**状态**：现行版本（基于各模块最新原型定稿整理）


## 一、项目概述

### 1.1 项目背景

基于Excel表格管理的教育信息化项目，需要将其迁移至线上系统进行规范化管理。项目涵盖从设备采购、交付实施到验收结算的全生命周期管理。

### 1.2 现状分析

| 现状     | 说明                             |
| -------- | -------------------------------- |
| 管理方式 | Excel表格分散管理                |
| 数据更新 | 手动维护，版本混乱               |
| 协作方式 | 文件传递，无法实时同步           |
| 进度跟踪 | 依赖人工汇总汇报                 |
| 资料归档 | 各阶段文档分散存储，难以统一管理 |

### 1.3 项目目标

- 将Excel内容线上化，实现数据集中管理
- 支持多用户协作，实时更新项目状态
- 项目计划（WBS）驱动任务执行，任务完成时上传佐证材料
- 提供标准模板下载，规范各阶段交付物格式
- 实现文件资料的统一管理、归档与批量下载
- 支持项目周报与校级周报的自动生成与导出
- 通过交付进展的单校全景详情实现"一校一档"全景洞察
- 支持多年度项目建设，按年份区分设备与任务
- 提供项目健康度综合评价与全局筛选能力
- 支持项目复盘与经验沉淀
- **支持可配置模板的汇报材料自动生成（Word/PPT）**
- **提供多维度交付进展视图（按学校/产线/系统）**
- **支持需求全流程管理的列表视图**
- **提供微信端任务维护与进度查询能力**
- **提供基于知识库的智能问答助手**

### 4.4 供应商管理

> **权限**：管理员、项目经理

#### 4.4.1 功能说明

本页**以设备为主体**：列表每行是一台设备，展示该设备对应的供应商及其联系方式，用于按设备维度查看与指定供应商。供应商本身的主数据通过页面上的「供应商主数据」入口单独维护。

#### 4.4.2 列表字段（主体：设备）

| 字段名   | 说明                                 | 来源                     |
| -------- | ------------------------------------ | ------------------------ |
| 设备名称 | 设备名称                             | devices.device_name      |
| 系统名称 | 设备所属系统                         | devices.system_name      |
| 型号     | 设备型号                             | devices.model            |
| 设备来源 | 三方外采 / 库存设备                  | devices.source           |
| 供应商   | 该设备的供应商，未指定时显示"未指定" | devices.supplier_id      |
| 联系人   | 供应商对接人，由供应商主数据带出     | suppliers.contact_person |
| 联系电话 | 供应商对接人电话，由供应商主数据带出 | suppliers.contact_phone  |

**筛选维度**：设备名称、系统名称、设备来源、供应商（含"未指定"）

#### 4.4.3 供应商主数据字段

| 字段名     | 类型         | 说明            | 必填 |
| ---------- | ------------ | --------------- | ---- |
| 供应商名称 | 文本（唯一） | 供应商/厂家全称 | 是   |
| 联系人     | 文本         | 维护对接人姓名  | 是   |
| 联系电话   | 文本         | 维护对接人电话  | 是   |
| 联系邮箱   | 文本         | 对接人邮箱      | 否   |
| 备注       | 文本域       | 说明            | 否   |

#### 4.4.4 业务规则
- 一个供应商可对应多台设备，一台设备只有一个供应商（devices.supplier_id 单值外键）
- 设备来源为「库存设备」时供应商可为空；来源为「三方外采」时应指定供应商
- 已被设备关联的供应商不可直接删除，需先解除设备关联
- 供应商联系方式只在主数据维护一处，设备列表只读展示，避免同一供应商在多台设备上填写不一致

#### 4.4.5 功能清单
- 设备-供应商列表查看与筛选
- 单台指定供应商 / 勾选后批量指定供应商
- 供应商主数据：列表查看、新增/编辑/删除
- 导出 Excel

#### 4.6.2 智能化功能

**字典值自动生成**:

- **生成规则**:
  1. 优先匹配常用词组映射表 (如"平台"→"pingtai", "科创"→"kechuang", "元宇宙"→"yuanyuzhou")

  4. 限制最大长度20字符,仅保留小写字母/下划线/数字
- **用户操作**: 自动生成后仍可手动修改,提供"🔄重新生成"按钮

**排序号自动计算**:
- **触发时机**: 用户在"字典类型"输入框失焦时自动计算
- **计算规则**:
  1. 查询该字典类型现有最大排序号
  2. 新排序号 = 最大值 + 10 (预留间隔便于后续插入)
  3. 新类型首次添加排序号为10
- **用户操作**: 自动计算后只读显示(灰色背景),不可手动修改

**用户体验增强**:
- 每个输入框下方显示💡提示说明使用方法
- 字段标签更清晰: "字典标签(显示文本)" + "字典值(内部代码)"

## 五、全局交互规范

### 5.1 全局筛选器

顶部导航增加**全局筛选栏**，所有业务模块统一响应：

| 筛选维度 | 类型   | 选项                                                         | 默认值 |
| -------- | ------ | ------------------------------------------------------------ | ------ |

**筛选逻辑**：全局筛选器与各模块独立筛选为**叠加关系**（AND逻辑），模块独立筛选进一步缩小范围。顶部显示当前生效的筛选条件，用户可快速清除。

### 5.2 列表页搜索规范

所有列表页统一搜索交互：
- **关键词搜索框**：模糊匹配当前列表关键字段
- **高级筛选**：点击展开更多筛选条件
- 搜索框位于列表上方左侧，筛选按钮位于右侧

### 5.2A 表格文本溢出规范（全局，所有表格/卡片适用）

- **不允许换行**：单元格文本统一 `white-space: nowrap`，不因内容长而换行撑高行。
- **省略号截断**：超出列宽的部分用省略号（…）截断（`overflow: hidden; text-overflow: ellipsis`）。
- **悬浮显示完整内容**：鼠标悬停在被截断的单元格上时，通过 `title` 属性或 Tooltip 组件显示完整文本。
- 适用范围：所有列表、甘特图、看板卡片等含文本的展示组件。

### 5.3 删除操作规范

所有删除操作增加二次确认弹窗：
- 提示："确定要删除【记录名称】吗？此操作不可恢复"
- 如果该记录被其他数据引用，提示："该记录已被引用，无法删除"

### 5.4 批量操作规范

所有列表页（项目计划、设备信息、风险管理）支持批量操作：

- 列表左侧增加复选框，支持全选/取消全选
- 选中记录后，列表顶部出现批量操作栏
- 批量操作选项：
  - **批量更新状态**：选中多条记录，统一变更状态
  - **批量分配责任人**：选中多条记录，统一分配责任人
  - **批量删除**：选中多条记录，统一删除（二次确认）
- 批量操作执行前二次确认
- 批量操作结果反馈（成功/失败条数）

### 5.5 数据下钻规范

所有展示统计数据、列表数据、汇总数据的页面，均需支持下钻能力。

#### 5.5.1 定义

**下钻**：用户点击某个数据元素（数字卡片、列表行、图表节点）后，系统跳转或弹出该数据对应的明细页面，查看更详细的数据。

#### 5.5.2 两种下钻模式

| 模式                  | 说明                         | 适用场景                            |
| --------------------- | ---------------------------- | ----------------------------------- |
| **页面跳转**          | 点击后从当前页面跳转到新页面 | 仪表板卡片点击 → 跳转到列表页       |
| **详情弹窗（Modal）** | 点击后在当前页面弹出居中浮层 | 列表页某一行 → 弹出该记录的详情浮层 |

#### 5.5.3 下钻触发方式

| 元素类型           | 触发方式               | 交互反馈                               |
| ------------------ | ---------------------- | -------------------------------------- |
| 数字卡片（仪表板） | 点击卡片任意区域       | 鼠标悬停变为手型，点击后跳转           |
| 列表行             | 点击行任意区域         | 鼠标悬停变为手型，点击后弹出详情       |
| 表格中的关联字段   | 点击字段值             | 字段变为蓝色可点击样式，点击后弹出详情 |
| 图表节点           | 点击柱子/折线点/扇形区 | 鼠标悬停变为手型，点击后跳转           |
| 带筛选条件的跳转   | 点击后带参数           | URL 携带筛选参数，列表自动过滤         |

#### 5.5.4 下钻模式选择

| 场景                        | 下钻模式              | 说明                                   |
| --------------------------- | --------------------- | -------------------------------------- |
| 仪表板数字卡片 → 列表页     | **页面跳转**          | 需要展示完整列表，支持进一步筛选       |
| 图表点击 → 筛选列表         | **页面跳转**          | 带上筛选参数跳转                       |
| 列表页行 → 详情页           | **详情弹窗（Modal）** | 查看单个记录的完整信息，不离开当前页面 |
| 关联字段点击 → 关联对象详情 | **详情弹窗（Modal）** | 如点击学校名，弹出该校详情             |

#### 5.5.5 详情弹窗（Modal）标准

- **类型**：统一使用居中弹窗（Modal），不再使用右侧抽屉（Drawer）。
- **宽度**：约 560px（居中显示）
- **标题**：显示记录名称 + "详情"
- **内容**：字段列表逐行展示（键值对形式）
- **操作**：底部放置"关闭""编辑"等按钮，可含"创建子任务"等场景化操作
- **关闭方式**：点击"×"、点击遮罩层、按 ESC 键、点击"关闭"按钮，均可关闭
- **命名遗留说明**：设备信息原型视觉与行为已是居中弹窗（Modal），但 CSS 类名/JS 函数名仍沿用 `drawer`/`openDetail` 字样，属命名遗留，开发时统一按 Modal 实现

#### 5.5.6 下钻跳转目标

| 来源                  | 点击元素   | 跳转目标                           |

| 列表页 - 关联字段     | 关联字段值 | 关联对象的详情弹窗（Modal）        |

#### 5.5.7 各模块下钻场景汇总

| 模块            | 下钻来源         | 跳转目标                           |
| --------------- | ---------------- | ---------------------------------- |

#### 5.5.8 下钻层级限制

| 层级   | 说明                                |
| ------ | ----------------------------------- |
| 第一层 | 仪表板 → 列表页                     |
| 第二层 | 列表页 → 详情弹窗（Modal）          |
| 第三层 | 详情弹窗 → 关联数据列表（页面跳转） |

> **原则**：下钻深度不超过 3 层，避免用户迷失。超过 3 层的数据，在详情页中通过"查看全部"按钮跳转。
>
> **详情交互规范**：二级下钻的详情统一采用**居中弹窗（Modal）**，不再使用右侧抽屉（Drawer）。项目计划、交付进展、风险管理、设备信息均采用居中弹窗。（注：设备信息原型的 CSS 类名/JS 函数名仍沿用 `drawer` 字样，但视觉与行为已是居中模态，属命名遗留，开发时统一按 Modal 实现即可。）

#### 5.5.9 下钻交互反馈

| 场景         | 交互细节                                               |
| ------------ | ------------------------------------------------------ |
| 鼠标悬停     | 下钻元素显示下划线或背景色变化，鼠标变为手型           |
| 点击后       | 如果数据量小，瞬间响应；数据量大时，显示加载状态       |
| 跳转后的列表 | 自动应用筛选条件（URL 参数），用户可清除筛选查看全部   |
| 空状态       | 如果下钻后无数据，显示"暂无数据"占位，并提供"返回"按钮 |

## 六、业务模块

### 6.1 首页（项目概览）

#### 6.1.1 功能定位

首页是**项目整体情况的总览页面**，让项目经理在打开系统后 30 秒内完成"判断项目状态 → 定位关键问题 → 确认个人待办"的决策闭环。首页只承载"判断依据"，不承载全部细节，明细一律下钻到对应模块查看。

#### 6.1.2 顶部卡片区（项目规模总览）

展示 7 个关键规模指标卡片，均支持下钻：

| 卡片     | 含义                   | 数据来源                                             |
| -------- | ---------------------- | ---------------------------------------------------- |
| 覆盖学校 | 项目总学校数           | schools 表                                           |
| 重点学校 | 标记为重点的学校数     | schools.is_key                                       |
| 系统总数 | 项目系统总数           | systems 表（is_enabled=1）                           |

| 产线类型 | 生产线种类数           | production_lines 表                                  |
| 外采设备 | 需外部采购的设备种类数 | devices 表（source='三方外采'，按 device_name 去重） |
| 硬件总数 | 硬件设备总台数         | devices 表（type='硬件' 求和 quantity）              |

> **数据来源说明**：设备字典表（device_systems）已于 2026-07-28 删除，所有设备相关统计直接从 devices 表查询。

#### 6.1.3 进度区（三栏+整体进度）

**整体进度展示规则**（置顶）：
- 整体进度条展示在进度区顶部，三栏之前
- 默认显示整体进度百分比（如 68%）
- 计算公式默认隐藏，鼠标悬停时显示：`已完成末级任务数 / 总末级任务数`

**三栏进度明细**：

| 栏目             | 展示方式   | 说明                                                         |
| ---------------- | ---------- | ------------------------------------------------------------ |
| 学校交付进度     | 环形图     | 6 种状态分布（待启动/装修中/安装中/调试中/培训中/已完成），标注重点学校。环形图尺寸自适应容器 |
| 硬件交付进度     | 环形图     | 5 种状态分布（待发货/已到货/已安装/已调试/运行中）。环形图尺寸自适应容器 |
| 软件平台交付进度 | 进度条列表 | 4 个模块（数智工作台/教育数据指挥中心/智能应用创编平台/应用能力服务）。**进度条颜色与状态对应**：已上线=绿色(#52c41a)、测试中=橙色(#fa8c16)、开发中=蓝色(#1677ff) |

各环形图/进度条支持点击下钻到对应模块的筛选列表。

#### 6.1.4 整体进度计算规则

整体进度 = 已完成末级任务数 / 总末级任务数

**定义**：
- **末级任务**：`work_content_l4` 非空的任务（L4为统计口径）
- **已完成**：`status = '已完成'`
- **无加权**：所有末级任务权重相等，不区分学校/硬件/软件维度

> 2026-07-26 定稿，废弃原「学校30% + 硬件40% + 软件30%」加权公式。详见业务规则说明.md §一。

**分项完成率**（用于三栏展示）：

| 维度       | 计算公式                 |
| ---------- | ------------------------ |
| 学校完成率 | 已验收学校数 / 总学校数  |
| 硬件完成率 | 运行中设备数 / 总设备数  |
| 软件完成率 | Σ各软件模块进度 / 模块数 |

#### 6.1.5 里程碑区

关键里程碑达成情况，以甘特条形式展示。

**表结构**：`阶段 | 任务 | 时间轴(甘特) | 开始日期 | 结束日期 | 完成状态`

**列宽规范（固定宽度，不允许内容撑开）**：
- 阶段列：120px
- 任务列：180px
- 甘特图列：占据剩余宽度，最小 400px
- 计划开始时间列：120px（完整显示 yyyy-mm-dd 格式）
- 计划完成时间列：140px（完整显示 yyyy-mm-dd 格式）
- 状态列：100px（完整显示"已完成/进行中/未开始"）

**表头与内容对齐**：全部列（表头 + 内容）均**居中显示**。

**通用表格规则**（适用于首页所有表格：里程碑、项目风险跟踪等）：
- 每一列设置固定宽度，采用 `table-layout: fixed` 强制固定布局，不允许内容自动撑开列宽
- 超出部分用省略号（…）截断，鼠标悬停显示完整内容（title 属性或 Tooltip 组件）
- 表格总宽度超出容器时，给表格容器增加 `overflow-x: auto`，允许横向滚动查看完整内容，而非压缩列宽或强制换行

**时间轴展示**：
- 月份刻度显示在时间轴(甘特)列的**表头**上(如 7月~12月),不在每行重复
- 月份范围根据里程碑任务的开始/结束日期自动匹配
- 甘特条相对位置和宽度根据任务日期计算得出

**完成状态枚举**：未开始 / 进行中 / 已完成 / 已延期（状态为枚举值，不展示完成数量）

**交互**：点击里程碑行下钻到该任务的明细页。

#### 6.1.6 项目风险跟踪区

**表字段**：`风险等级 | 风险描述 | 影响描述 | 应对措施 | 进展说明 | 责任人 | 状态`

**列宽规范（固定宽度）**：风险等级 90px、风险描述 180px、影响描述 160px、应对措施 160px、进展说明 160px、责任人 120px、状态 100px。

**表头与内容对齐**：全部列（表头 + 内容）均**居中显示**。适用[6.1.5](#615-里程碑区)所述通用表格规则（固定列宽、省略号截断+悬停显示、超宽横向滚动）。

**状态枚举**：待处理 / 处理中 / 已关闭

| 展示内容 | 说明                                                        |
| -------- | ----------------------------------------------------------- |
| 筛选规则 | 首页默认仅展示活跃风险（状态 ≠ 已关闭）                     |
| 排序规则 | ① 按等级：高 → 中 → 低<br>② 同等级内按状态：待处理 → 处理中 |
| 展示数量 | 默认展示 TOP 5 活跃风险，"查看全部"跳转风险管理模块         |

**交互**：点击某条风险 → 弹出风险详情弹窗（Modal）；点击"查看全部" → 跳转 /risks。

#### 6.1.7 待办区

**布局**：项目待办、我的待办各自为一个**独立框**，并排展示，两框列宽一致。

**独立筛选**：每个框顶部各带一组筛选按钮（本月 / 本周 / 今日），**默认显示"本周"**。两框筛选相互独立，分别对各自的待办列表按时间范围过滤（不是对全部待办统一筛选）。

**两框内容**：

| 区域     | 权限                         | 说明                                                         |
| -------- | ---------------------------- | ------------------------------------------------------------ |
| 项目待办 | 所有用户可见（校园经理只读） | 展示未完成的**末级待办**，管理员/项目经理可指定负责人、编辑；校园经理视角下操作按钮不显示（而非置灰） |
| 我的待办 | 所有用户可见                 | 当前用户的**末级待办**，支持标记完成、编辑、转办（全角色）   |

**末级待办联动规则**（代码逻辑实现，页面不展示说明文字）：
- 项目待办和个人待办统一展示"末级待办"（最细颗粒度待办）的完成情况
- 当下级待办全部完成后，上级待办自动维护为已完成
- 待办支持多级树形结构，联动更新保证上级状态与下级一致

**时间筛选口径**：按待办的截止日期（due_date）判断归属本月 / 本周 / 今日。

待开始 → 进行中 → 已完成（材料齐全）
                  → 待补材料（材料缺失） → 上传材料后 → 已完成
                  → 已延期（超时）

#### 6.2.5A 父子任务状态联动规则

WBS 为多级层级结构，父任务状态由子任务驱动，规则如下：

1. **单一数据源**：同一任务在**首页里程碑、项目计划页、交付进展页**三处展示，**任一处维护后所有页面自动同步**。同一任务全局只有一个状态和一份字段信息，不允许出现两条状态或字段不一致。
2. **子任务开始 → 父任务自动开始**：当任一子任务状态变为"进行中"，其所有祖先父任务自动变为"进行中"（若原为"待开始"）。
3. **子任务全部完成 → 父任务自动完成**：当某父任务下全部直接子任务变为"已完成"，该父任务自动变为"已完成"（逐级向上传导）。
4. **子任务全部待开始 → 父任务待开始**：当某父任务下全部直接子任务均为"待开始"，该父任务自动变为"待开始"。
5. **父任务不可越级完成**：只要父任务存在未完成的子任务，**系统禁止**手动将父任务改为"已完成"，并提示"该任务还有 N 个子任务未完成，父任务状态由子任务驱动，请先完成所有子任务"。
6. **状态改动联动展示**：
   - 甘特图视图：改动任务状态时，色条颜色、进度百分比自动联动（已完成→绿色+100%、待开始→灰色+0%、进行中→蓝色+实际进度）
   - 看板视图：改动任务状态后，卡片自动从当前列移动到对应状态列（如"进行中"卡片改为"已完成"后自动跳转到"已完成"列）

#### 6.2.5B 任务详情弹窗

列表行或看板卡片点击任务名称 → 弹出**居中详情弹窗（Modal）**（非右侧抽屉），展示单个任务的完整信息。

**取数**：调用 `GET /api/v1/project-plan/tasks/{id}` 获取单任务详情。

**展示字段**（键值对逐行）：任务名称、任务编码、任务层级、状态、优先级、责任人、关联学校、计划工期（计划开始～计划结束）、实际结束、进展说明、交付物。

**任务层级（level）显示规则**：后端**不返回独立的 `level` 字段**，层级由 L1-L5 哪一级有值推算得出，取有值的最深一级：

| 判断（从深到浅）       | 显示 |
| ---------------------- | ---- |
| `work_detail_l5` 有值  | L5   |
| `work_content_l4` 有值 | L4   |
| `task_package_l3` 有值 | L3   |
| `sub_phase_l2` 有值    | L2   |
| 以上皆空               | L1   |

**任务名称显示规则**：同样取最深一级的内容（L5→L4→L3→L2→L1 回退）。

**底部操作**：关闭、➕创建子任务、✏️编辑当前任务。

**关闭方式**：点击"×"、遮罩层、ESC 键、"关闭"按钮均可关闭。

#### 6.2.6 里程碑取数与延期判断

**里程碑取数规则**：
- 默认取 **L1 项目阶段 + L2 子阶段** 作为里程碑节点
- 不限制条数（根据实际项目阶段数量动态生成）
- 首页里程碑与项目计划页共用同一数据源

**里程碑延期判断**（与WBS任务延期逻辑一致）：
- 系统每日定时检查所有里程碑
- 当前日期超过计划完成日期且状态≠"已完成"时，状态自动变更为"已延期"

#### 6.2.7 时间筛选条件

项目计划页支持按任务截止日期筛选：
- 今日任务
- 本周任务
- 上周任务
- 本月任务
- 自定义时间范围

#### 6.2.8 WBS自动生成规则

**触发条件**：设备信息模块新增设备记录时自动生成。

**仅生成建设年份≤当前年份的设备任务**（如当前2026年，只生成2026年及以前设备任务）。

**计划时间映射**：
- 完成设备到货：取设备信息的"到货计划时间"
- 完成设备安装：到货计划时间 + 3天
- 完成设备调试：安装计划时间 + 2天
- 完成教师培训：调试计划时间 + 5天

**设备编辑后再次生成规则**：
- 已有任务 → 更新计划时间，不新增
- 新增的L4任务 → 新增
- 不再需要的L4任务 → 标记为孤儿任务

**事务一致性**：设备记录保存与WBS任务生成在同一数据库事务中，全部成功或全部回滚。

#### 6.2.9 孤儿任务处理

孤儿任务在列表中特殊标记（灰色背景 + "已失效"标签），系统每周定时提醒项目经理存在孤儿任务，支持手动删除或重新关联其他设备记录。

#### 6.2.10 功能清单
- WBS树形视图（5级展开/折叠）
- 列表视图（支持筛选、**批量操作**）
- 自动生成WBS（基于设备台账）
- 手动新增 / 编辑 / 删除任务
- 批量导入（Excel，支持解析L1-L5层级）
- 任务状态变更 → 触发材料校验与"待补材料"状态
- 佐证材料上传与查看（模板自动匹配与下载）
- 进度统计（完成百分比）


### 6.3 交付进展

#### 6.3.1 模块定位

交付进展是**学校维度交付全景面板**，整合了学校看板和培训管理的功能，用于查看项目整体的交付状态和分学校的交付进展。

> **架构说明**：
> - **学校看板**不作为独立模块，其"一校一档"全景功能融合到交付进展第二层单校详情
> - **培训管理**不作为独立菜单，入口与功能并入交付进展（培训字段定义见 6.3.6）

#### 6.3.2 页面层级结构

**一层视图（项目级）**：

**顶部统计卡片**（6个状态，与首页"学校交付进度"一致）：
- 待启动
- 装修中
- 安装中
- 调试中
- 培训中

#### 6.4.3 设备状态与WBS任务状态联动

**联动原则**：以WBS任务状态为准。WBS→设备为自动同步（主要），设备→WBS为提醒（辅助）。

**WBS→设备（自动同步）**：

| WBS任务L4内容 | 触发后设备状态变更 |
| ------------- | ------------------ |
| 完成设备到货  | → 已到货           |
| 完成设备安装  | → 已安装           |
| 完成设备调试  | → 已调试           |
| 完成设备验收  | → 运行中           |

**设备→WBS（提醒）**：手动变更设备状态时，发送站内消息提醒责任人更新WBS状态。

**一致性规则**：WBS状态回退时，设备状态不回退（物理状态不随计划回退）。

#### 6.4.4 序列号搜索规则

- **序列号范围格式**（三种）：
  - 单个序列号：如"SN12345"
  - 纯数字范围：如"1-50"（表示1到50号）
  - 字母数字混合范围：如"A001-A050"（前缀"A"一致，数字部分001到050递增）
- **范围校验**：
  - 范围格式必须为"起始-结束"，起始值需小于结束值
  - 混合格式：起始与结束的字母前缀必须一致，仅数字部分递增
- **搜索逻辑**：
  - 用户输入单个序列号（如"40"或"A030"），系统自动匹配包含该序列号的范围记录
  - 支持精确匹配、数字范围匹配、字母数字混合范围匹配
  - 示例1：搜索"40" → 匹配到序列号范围"1-50"的设备记录
  - 示例2：搜索"A030" → 匹配到序列号范围"A001-A050"的设备记录
  - 匹配后显示该设备所在学校和详细信息

### 6.5 风险管理

#### 6.5.1 模块定位

采用**简化风险管理模型**：不关联WBS任务，风险等级由责任人**手工评定**（不自动用概率×影响矩阵计算）。风险跟踪以**自由文本进展说明**为主，降低维护成本，适配快速迭代的项目场景。

> **设计理念**：完整重量级模型（概率×影响矩阵自动算等级、WBS任务关联、自动进度计算）在中小型教育信息化项目中维护成本高、使用率低。本系统简化为：**保留风险等级（手工选高/中/低）**，去掉概率、影响两个矩阵下拉与自动计算、去掉WBS任务关联，聚焦风险本身的描述、应对和进展跟踪。

#### 6.5.2 数据字段

| 字段名   | 类型           | 说明                         | 必填 |
| -------- | -------------- | ---------------------------- | ---- |
| 风险描述 | 文本域         | 风险详细描述                 | 是   |
| 风险等级 | 下拉框         | 高/中/低，**手工评定**       | 是   |
| 触发条件 | 文本域         | 什么情况下该风险会被触发     | 否   |
| 影响描述 | 文本域         | 对进度/质量/成本的具体影响   | 否   |
| 应对策略 | 文本域         | 风险应对策略                 | 否   |
| 进展说明 | 文本域         | 应对策略执行进展（自由文本） | 否   |
| 责任人   | 下拉框（用户） | 风险负责人                   | 是   |

> **已去除字段**：概率、影响（原概率×影响矩阵，用于自动算等级）、风险等级的自动计算逻辑、应对计划完成时间、风险-应对任务关联表（risk_tasks）。风险等级改为手工选择。

#### 6.5.3 功能清单

#### 6.7.4 一键催办功能

## 八、数据导入规范

### 8.1 通用规则
- 每个模块提供标准Excel模板下载

### 8.2 WBS导入增强

支持Excel导入时**自动解析L1-L5层级结构**：
- 模板列：L1阶段、L2子阶段、L3任务包、L4工作内容、L5工作明细、计划开始时间、计划结束时间、责任人账号、关联学校编码、关联阶段类型
- 系统自动识别层级关系，生成树形结构
- 支持多学校批量导入

### 8.3 设备批量导入

提供标准Excel模板，支持一次导入多条设备记录：
- 模板列：系统名称、设备名称、数量、分配学校编码、安装位置、设备来源、供应商名称、到货计划时间、备注
- 校验通过后统一提交

### 8.4 数据迁移方案

| 步骤        | 内容                                               |
| ----------- | -------------------------------------------------- |
| 1. 模板下载 | 系统提供完整导入模板                               |
| 2. 数据清洗 | 建议用户先进行去重、格式标准化                     |
| 3. 分批导入 | 支持大文件分批处理，每批建议500条                  |
| 4. 导入报告 | 导入后生成报告（成功条数、失败条数、失败原因列表） |


## 九、通知机制

### 9.1 通知类型

| 通知场景         | 触发条件                               | 接收人            | 方式                |
| ---------------- | -------------------------------------- | ----------------- | ------------------- |
| 风险响应提醒     | 风险状态="待处理"且责任人未响应超过3天 | 风险责任人        | 站内消息            |
| 任务分配         | WBS任务被分配/变更责任人               | 新责任人          | 站内消息            |
| 任务到期提醒     | 计划结束时间前3天仍未完成              | 责任人            | 站内消息            |
| 材料待补充       | 任务状态变为"待补材料"                 | 任务责任人        | 站内消息            |
| 设备状态变更提醒 | 设备状态被手动变更                     | 关联WBS任务责任人 | 站内消息            |
| 孤儿任务提醒     | 系统每周定时检查存在孤儿任务           | 项目经理          | 站内消息            |
| 催办通知         | 项目经理在交付材料库发起催办           | 被催办用户        | **站内消息 + 邮件** |

### 9.2 邮件通知配置

**系统要求**：
- 系统后台配置SMTP邮件服务（发件邮箱、SMTP服务器、端口、认证信息）
- 用户需在个人资料中维护邮箱地址
- 邮件发送失败时记录错误日志，不影响站内消息发送

**邮件内容模板**：
- 标题：【GX项目交付系统】催办通知 - 缺失材料提醒
- 正文：您好，您有以下交付材料尚未上传，请及时补充：[缺失材料清单] [所属学校] [任务链接]

### 9.3 功能清单
- 消息列表（按时间倒序）
- 消息详情查看
- 标记已读/全部已读
- 未读消息数量角标提示
