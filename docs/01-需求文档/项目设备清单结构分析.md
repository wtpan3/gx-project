## 一、清单是什么

本项目（高新区"AI+教育"）的**完整交付物清单**，共 **359 条**，覆盖 3 大模块、25 个系统。它不只是"设备"清单，而是混合了硬件、软件、服务、开发、施工五种性质的**全交付物规划基线**。

层级：**模块 → 系统名称 → 设备名称(大类) → 设备名称(子项)**，数量已按 **3 年度 + 5 学校**二维拆分。

## 五、四分区共识 ⭐（2026-07-23 与用户逐条确认，核心结构决策）

清单 359 行按交付物性质分四类，各归不同页面管理。**这是后续所有模块设计的分区依据**：

| 归属页面 | 行数 | 包含类型 | 交付特征 |
|---------|-----|---------|---------|
| **设备信息 / 设备字典**（硬件看板） | 287 | 硬件225 + 软件62 | 序列号、发货→到货→安装→调试→运行 五态 |
| **软件看板**（新增页面） | 44 | 定制开发13 + 软件服务29 + 资源服务2 | 人月 / 系统·3年 / 授权包 |
| **服务进展**（新增页面） | 16 | 技术服务15（=教育大脑"应用能力服务"）+ 服务1（体测） | 按周期 / 人次·年 |
| **项目计划 / WBS**（并入，不单开页） | 12 | 施工11 + 环境集成1（类型空的那行） | 工程任务节点、验收 |

**合计**：287 + 44 + 16 + 12 = **359** ✅ 零遗漏

**决策要点**：
1. **配套软件跟硬件走**：软件(62)不单列，并入设备信息/字典，随所属系统的硬件一起管。纯软件系统（如"教师智能助手"）也进设备信息，作为可交付物。
2. **教育大脑的开发与软件服务走软件看板**：定制开发13 + 软件服务29 + 资源服务2 = 44 行。资源服务（大模型流量包/工具包）归软件看板。
3. **服务进展只收两块**：教育大脑"应用能力服务"（技术服务15）+ 常规采购"中小学生体测服务"（1）。
4. **施工不单开页**：施工11 + "环境设计与系统集成"1，作为 WBS 工程任务节点并入现有项目计划模块跟踪。
5. **新增页面 2 个**：软件看板、服务进展。

## 六、与现有原型/需求的差异（校准 TODO）

1. **缺"模块"层**：现原型只有"系统→设备"两级，清单是"模块→系统→设备大类→子项"四级。
2. **设备名称两级**（大类+子项），原型按一级处理。
3. **类型枚举**：需求 §4.3 写 3 种（硬件/软件/服务），清单实际 **8 种**。
4. **采购类型枚举**：原型用 2 种，清单实际 **5 种**。
5. **产线**：清单有独立"产线"列（10 个值），对应此前定的方案A（产线挂系统层）。
6. **分年度 + 分学校数量**：清单核心维度，现原型完全未体现。
7. **单位 24 种**且含时间维度，非简单"台/套/个"。

> 规格（品牌/型号/参数）当前多数未填，甲方后续补充；硬件(225行)届时会有完整规格。
