## 一、整体进度计算

### 1.1 核心公式

整体进度 = 已完成末级任务数 / 总末级任务数

**定义**：
- **末级任务**：`work_content_l4` 非空的任务（L4为统计口径）
- **已完成**：`status = '已完成'`
- **无加权**：所有末级任务权重相等，不区分学校/硬件/软件维度

### 1.2 分项完成率

| 维度       | 计算公式                 |
| ---------- | ------------------------ |
| 学校完成率 | 已验收学校数 / 总学校数  |
| 硬件完成率 | 运行中设备数 / 总设备数  |
| 软件完成率 | Σ各软件模块进度 / 模块数 |

> 分项完成率用于进度区三栏展示（首页环形图/进度条），但不参与整体进度计算。


## 二、首页状态判断（健康度）

| 状态     | 颜色 | 判定条件                                                     |
| -------- | ---- | ------------------------------------------------------------ |
| **正常** | 🟢    | 全部满足：①无延期>7天任务 ②无待处理风险项 ③进度≥计划80%      |
| **关注** | 🟡    | 满足任一：①存在延期3-7天任务 ②存在待处理风险项 ③进度<计划80% |
| **异常** | 🔴    | 满足任一：①存在延期>7天任务 ②存在≥2个待处理风险项 ③进度严重滞后 |

> 风险管理采用简化模型（风险等级手工评定），健康度按风险状态（待处理/处理中/已关闭）判断。


## 三、待办联动规则

### 3.1 末级联动

当某个待办的所有子待办全部为"已完成"时，该待办自动标记为"已完成"。

> 首页项目待办和个人待办仅展示末级待办（最细颗粒度）。

### 3.2 父任务自动开始

当任一子任务状态变为"进行中"时，其所有祖先父任务自动变为"进行中"（若原为"待开始"）。

### 3.3 父任务不可越级完成

只要父任务还存在未完成的子任务，系统禁止手动将父任务改为"已完成"。

**提示信息**：`该任务还有 N 个子任务未完成，父任务状态由子任务驱动，请先完成所有子任务。`

### 3.4 操作权限

| 角色     | 指定负责人 | 编辑待办 | 维护自己待办状态 | 转办 |
| -------- | ---------- | -------- | ---------------- | ---- |
| 管理员   | ✅          | ✅        | ✅                | ✅    |
| 项目经理 | ✅          | ✅        | ✅                | ✅    |
| 校园经理 | ❌          | ❌        | ✅                | ✅    |


## 四、WBS自动生成规则

### 4.1 触发条件

设备信息模块**新增设备记录**时自动生成WBS任务。

### 4.2 生成范围

**仅生成建设年份 ≤ 当前年份的设备任务**（如当前2026年，只生成2026年及以前设备任务）。

### 4.3 计划时间映射

| WBS任务      | 时间计算                   |
| ------------ | -------------------------- |
| 完成设备到货 | 取设备信息的"到货计划时间" |
| 完成设备安装 | 到货计划时间 + 3天         |
| 完成设备调试 | 安装计划时间 + 2天         |
| 完成教师培训 | 调试计划时间 + 5天         |

### 4.4 设备编辑后处理

| 场景             | 处理方式                        |
| ---------------- | ------------------------------- |
| 已有任务         | 更新计划时间，不新增            |
| 新增的L4任务     | 新增对应WBS任务                 |
| 不再需要的L4任务 | 标记为孤儿任务（`is_orphan=1`） |

### 4.5 事务一致性

设备记录保存与WBS任务生成**在同一数据库事务中**，全部成功或全部回滚。


## 五、孤儿任务处理

- **标记**：灰色背景 + "已失效"标签
- **提醒**：系统每周定时提醒项目经理存在孤儿任务
- **操作**：支持手动删除或重新关联其他设备记录


## 六、风险管理规则（简化模型）

### 6.1 模型说明

采用简化风险管理模型，**保留风险等级（高/中/低，手工评定）**，去掉概率×影响矩阵自动计算。

### 6.2 字段定义

| 字段     | 说明                         | 必填 |
| -------- | ---------------------------- | ---- |
| 风险描述 | 风险详细描述                 | 是   |
| 风险等级 | 高/中/低（手工选择）         | 是   |
| 触发条件 | 什么情况会触发               | 否   |
| 影响描述 | 对进度/质量/成本的影响       | 否   |
| 应对措施 | 风险应对策略                 | 否   |
| 进展说明 | 应对策略执行进展（自由文本） | 否   |
| 责任人   | 风险负责人                   | 是   |
| 状态     | 待处理/处理中/已关闭         | 是   |
| 关联学校 | 允许为空                     | 否   |

**已删除字段**：概率、影响（原矩阵下拉）、风险等级自动计算、应对计划完成时间、risk_tasks关联表

### 6.3 状态与等级

**状态枚举**：
| 状态   | 颜色      | 说明                 |
| ------ | --------- | -------------------- |
| 待处理 | 🔵 #1677ff | 已登记未采取措施     |
| 处理中 | 🟠 #fa8c16 | 正在应对             |
| 已关闭 | ⚪         | 已解决（首页不显示） |

**风险等级**（手工评定）：
| 等级 | 颜色      |
| ---- | --------- |
| 高   | 🔴 #ff4d4f |
| 中   | 🟠 #fa8c16 |
| 低   | 🟢 #52c41a |

### 6.4 首页展示规则

- 展示范围：活跃风险（状态 ≠ 已关闭）
- 排序规则：等级（高→中→低）+ 状态（待处理→处理中）
- 数量限制：TOP 5
- 交互：点击"查看全部"跳转风险管理模块；点击风险行 → 风险详情弹窗

### 6.5 提醒规则

状态="待处理"且责任人未响应超过 **3天** → 站内消息提醒风险责任人。


## 七、关联阶段类型自动推荐规则

WBS任务创建时，系统根据 L2子阶段 + L3任务包关键词 自动推荐关联阶段类型（用户可手动修改）：

| L2子阶段     | 判断条件     | 自动推荐 |
| ------------ | ------------ | -------- |
| 硬件交付     | L3包含"到货" | 到货验收 |
| 硬件交付     | L3包含"安装" | 加电测试 |
| 硬件交付     | 其他         | 无       |
| 应用培训     | —            | 培训     |
| 竣工资料提交 | —            | 校级验收 |
| 业主验收会   | —            | 校级验收 |
| 其他         | —            | 无       |


## 八、里程碑状态映射

## 九、WBS父子任务状态联动规则

| 规则                          | 说明                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| 单一数据源                    | 同一任务在首页/项目计划/交付进展三处展示，任一处维护全局同步 |
| 子任务开始→父任务开始         | 任一子任务变"进行中" → 所有祖先父任务自动"进行中"（若原为待开始） |
| 全部子任务完成→父任务完成     | 某父任务下全部直接子任务"已完成" → 父任务自动"已完成"（逐级向上传导） |
| 全部子任务待开始→父任务待开始 | 某父任务下全部直接子任务"待开始" → 父任务自动"待开始"        |
| 父任务不可越级完成            | 存在未完成子任务时，禁止手动改父任务为"已完成"，给出拦截提示 |
| 状态改动联动展示              | 甘特图色条颜色自动联动；看板卡片自动移动到对应状态列         |


## 十、学校交付状态映射规则（待确认）

> ⚠️ 此规则涉及 schools 表存储态与交付进展展示态的映射，因学校态的问题比较多，开发到交付进展模块前**必须先确认**，再实现。

schools 表 `project_status` 存储态为：`未启动, 实施中, 试运行, 已验收, 维保中`

交付进展页展示态为 6 态：`待启动, 装修中, 安装中, 调试中, 培训中, 已完成`

**展示态由该校 WBS 的 L4 任务推进情况实时推算**：

| 展示态 | 判定条件（按该校 L4 任务）                   |
| ------ | -------------------------------------------- |
| 待启动 | 全部 L4 任务均为"待开始"                     |
| 装修中 | 有"场地/机房/装修"类任务处于进行中           |
| 安装中 | 有"设备安装"类任务处于进行中（且到货已完成） |
| 调试中 | 安装完成，有"设备调试"类任务进行中           |
| 培训中 | 调试完成，有"教师培训"类任务进行中           |
| 已完成 | 全部 L4 任务均为"已完成"                     |

> **风险点**：① WBS 自动生成只产出到货/安装/调试/培训 4 类任务，**无"装修"类**——若项目不单独建装修任务，则"装修中"状态取不到值，需确认是否保留该状态或改判定口径。② 多类任务并行进行时以哪个为准（建议取推进最靠后的阶段）。开发此逻辑前先确认，不擅自实现。
