### 变更1：多项目隔离机制

**影响范围**：9张核心表全部新增 `project_id INT` 字段，支持系统管理多个独立项目。

| schools         | +project_id（NOT NULL）                     | 20条→project_id=1  |
| dict_items      | +project_id（DEFAULT 1，NULL=全局共享）     | 29条→project_id=1  |
| wbs_tasks       | +project_id + requires_material + material_status | 64条→project_id=1  |
| devices         | +project_id（NOT NULL）                     | 1240条→project_id=1|
| trainings       | +project_id（NOT NULL）                     | 0条                |
| risks           | +project_id（NOT NULL）                     | 8条→project_id=1   |
| reports         | +project_id（NOT NULL）                     | 0条                |
| files           | +project_id + wbs_task_id + template_id     | 0条                |
| operation_logs  | +project_id（可为NULL，跨项目操作）         | 0条                |

**外键约束**：所有 project_id 字段均外键关联到 `project_info(id)`

### 变更2：模板管理架构重构

**templates 表**从 10 个字段扩展到 18 个字段：
- ① **删除** `stage` 字段（固定ENUM），改用关联表 `template_wbs_stages` 支持动态多层级关联
- ② **新增** `project_id` / `template_key` / `file_name` / `file_size` / `file_type` / `upload_by` / `download_count` / `is_latest` / `is_deleted`
- ③ `type` 从 ENUM 改为 VARCHAR(50)，从数据字典读取，支持交付类（7种）+ 报告类（5种）

**template_wbs_stages 关联表**（新建）：
- 支持一个模板关联多个 WBS 节点（L1/L2/L3任意层级）
- `is_required` 标记实现材料卡点机制

---

### 变更3：材料卡点机制

**wbs_tasks 表**新增 2 个字段：
- `requires_material TINYINT`：是否需要上传材料（由模板关联自动标记）
- `material_status ENUM('无要求','待上传','部分上传','已完成')`：材料完成状态

**files 表**新增 2 个字段：
- `wbs_task_id INT`：关联的 WBS 任务
- `template_id INT`：使用的模板

**业务规则**：
- 模板上传时勾选关联的 WBS 层级（如L2:设备安装），对应 wbs_tasks 记录自动 `requires_material=1`
- 用户在任务详情上传材料时，`files` 表记录关联 `wbs_task_id` + `template_id`
- 系统根据上传记录自动更新 `wbs_tasks.material_status`
- 任务标记"已完成"时，校验 `requires_material=1` 且 `material_status='已完成'`，否则拦截

---

### 变更4：数据字典扩充

新增 `模板类型` 分类（12条）：

- 汇报材料类：项目周报 / 项目月报 / 校级周报 / 校级月报 / 专项汇报

废弃 `关联阶段` 分类（5条），改用 `template_wbs_stages` 表动态关联。

```sql
CREATE TABLE schools (
    id INT PRIMARY KEY AUTO_INCREMENT,
    project_id INT NOT NULL DEFAULT 1 COMMENT '所属项目',
    code VARCHAR(50) UNIQUE NOT NULL COMMENT '学校编码',
    full_name VARCHAR(200) NOT NULL COMMENT '学校全称',
    region VARCHAR(100) NOT NULL COMMENT '所属区域',
    address VARCHAR(255) COMMENT '详细地址',
    campus_manager_id INT COMMENT '校园经理ID，关联users.id',
    contact_person VARCHAR(50) NOT NULL COMMENT '校方联系人',
    contact_phone VARCHAR(20) NOT NULL COMMENT '校方联系电话',
    project_status ENUM('未启动','实施中','试运行','已验收','维保中') DEFAULT '未启动' COMMENT '项目状态',
    is_key TINYINT DEFAULT 0 COMMENT '是否重点学校：1=是，0=否',
    remark TEXT COMMENT '备注',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES project_info(id),
    FOREIGN KEY (campus_manager_id) REFERENCES users(id) ON DELETE SET NULL,
```

### 2.5 templates - 模板表

> **架构变更说明（2026-07-28）**：
> - ① 删除 `stage` 字段，改用关联表 `template_wbs_stages` 支持一个模板关联多个 WBS 层级（L1/L2/L3）
> - ② `type` 从 ENUM 改为 VARCHAR(50)，从数据字典读取，支持交付类（7种）+ 报告类（5种）
> - ③ 新增版本管理机制：`template_key` 分组 + `is_latest` 标记
> - ④ 新增文件元信息：`file_name` / `file_size` / `file_type` / `upload_by` / `download_count`
> - ⑤ 新增 `project_id` 支持多项目隔离
> - ⑥ 新增 `is_deleted` 软删除标记

| 字段           | 类型         | 说明                                                  | 必填 |
| -------------- | ------------ | ----------------------------------------------------- | ---- |
| id             | INT          | 主键，自增                                            | 是   |
| project_id     | INT          | 所属项目                                              | 是   |
| template_key   | VARCHAR(50)  | 模板分组键（同一模板的多版本共用，如"到货验收表"）    | 是   |
| name           | VARCHAR(100) | 模板名称（含版本号，如"到货验收表-V2.0"）             | 是   |
| type           | VARCHAR(50)  | 模板类型（从数据字典"模板类型"读取）                  | 是   |
| file_path      | VARCHAR(500) | 服务器存储路径                                        | 是   |
| file_name      | VARCHAR(255) | 原始文件名（用户下载时的文件名）                      | 是   |
| file_size      | INT          | 文件大小（字节）                                      | 否   |
| file_type      | VARCHAR(50)  | 文件类型（docx/xlsx/pptx等）                          | 否   |
| version        | VARCHAR(20)  | 版本号（如V1.0）                                      | 是   |
| description    | TEXT         | 说明                                                  | 否   |
| status         | ENUM         | 启用/停用，默认"启用"                                 | 否   |
| is_latest      | TINYINT      | 是否最新版（同template_key组内），默认1              | 否   |
| is_deleted     | TINYINT      | 软删除标记，默认0                                     | 否   |

| updated_at     | DATETIME     | 更新时间                                              | 否   |

**业务规则：**
- 上传新版本时，同一 `template_key` 的旧版本自动 `is_latest=0, status='停用'`
- WBS 关联通过 `template_wbs_stages` 表配置，支持关联到 L1/L2/L3 任意层级
- 模板类型包含：交付材料类（到货验收表等7种）+ 汇报材料类（项目周报等5种）

**SQL建表语句：**
```sql
CREATE TABLE templates (
    id INT PRIMARY KEY AUTO_INCREMENT,
    project_id INT NOT NULL COMMENT '所属项目',
    template_key VARCHAR(50) NOT NULL COMMENT '模板分组键',
    name VARCHAR(100) NOT NULL COMMENT '模板名称',
    type VARCHAR(50) NOT NULL COMMENT '模板类型',
    file_path VARCHAR(500) NOT NULL COMMENT '服务器存储路径',
    file_name VARCHAR(255) NOT NULL COMMENT '原始文件名',
    file_size INT COMMENT '文件大小',
    file_type VARCHAR(50) COMMENT '文件类型',
    version VARCHAR(20) NOT NULL COMMENT '版本号',
    description TEXT COMMENT '说明',
    status ENUM('启用','停用') DEFAULT '启用' COMMENT '状态',
    is_latest TINYINT DEFAULT 1 COMMENT '是否最新版',
    is_deleted TINYINT DEFAULT 0 COMMENT '软删除标记',
    upload_by INT NOT NULL COMMENT '上传人',
    download_count INT DEFAULT 0 COMMENT '下载次数',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES project_info(id),
    FOREIGN KEY (upload_by) REFERENCES users(id),
    INDEX idx_project_type (project_id, type),
    INDEX idx_project_status (project_id, status, is_latest),
    INDEX idx_template_key (template_key, is_latest)
) COMMENT='模板表' DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```


### 2.5a template_wbs_stages - 模板-WBS阶段关联表

> **新增表（2026-07-28）**：支持模板与WBS任意层级（L1/L2/L3）的多对多关联，实现材料卡点机制。

| 字段        | 类型         | 说明                                         | 必填 |
| ----------- | ------------ | -------------------------------------------- | ---- |
| id          | INT          | 主键，自增                                   | 是   |
| template_id | INT          | 模板ID（外键→templates.id）                  | 是   |
| level       | ENUM         | 关联层级：L1/L2/L3                           | 是   |
| stage_value | VARCHAR(100) | 阶段值（实际的阶段名称，从WBS实时提取）      | 是   |
| is_required | TINYINT      | 是否强制上传（1=必须，0=可选），默认1        | 否   |
| created_at  | DATETIME     | 创建时间                                     | 否   |

**业务规则：**
- 一个模板可关联多个 WBS 节点（跨层级）
- `is_required=1` 时，对应 WBS 任务必须上传材料才能标记"已完成"
- `stage_value` 从 `wbs_tasks` 表的 `project_phase_l1` / `sub_phase_l2` / `task_package_l3` 实时提取

**SQL建表语句：**
```sql
CREATE TABLE template_wbs_stages (
    id INT PRIMARY KEY AUTO_INCREMENT,
    template_id INT NOT NULL COMMENT '模板ID',
    level ENUM('L1','L2','L3') NOT NULL COMMENT '关联层级',
    stage_value VARCHAR(100) NOT NULL COMMENT '阶段值',
    is_required TINYINT DEFAULT 1 COMMENT '是否强制上传',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (template_id) REFERENCES templates(id) ON DELETE CASCADE,
    UNIQUE KEY uk_template_level_stage (template_id, level, stage_value)
) COMMENT='模板-WBS阶段关联表' DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 三、枚举值定义

以下枚举值以 `ddl.sql` 建表语句为准，**开发时必须严格遵守**。

### 3.1 设备来源（devices.source）
- `三方外采`：从第三方供应商采购的设备
- `库存设备`：从自有库存调拨的设备

### 3.2 风险状态（risks.status）
- `已识别`：风险已登记，尚未采取措施
- `应对中`：正在采取措施应对
- `已关闭`：风险已解决或消除（首页不显示）

### 3.3 软件模块阶段（software_modules.phase）
- `需求收集` → `需求确认` → `软件开发` → `软件测试` → `软件部署` → `上线运行`

### 3.4 硬件设备状态（devices.status）
- `待发货` → `已到货` → `已安装` → `已调试` → `运行中`

### 3.5 WBS任务状态（wbs_tasks.status）
- `待开始` → `进行中` → `已完成` → `已延期` → `待补材料`

### 3.6 待办优先级（todos.priority）
- `高` / `中` / `低`

#### 4.3.3 todos - 待办表

| 字段               | 类型         | 说明                                       | 必填 | 唯一 |
| ------------------ | ------------ | ------------------------------------------ | ---- | ---- |
| id                 | INT          | 主键，自增                                 | 是   | 是   |

| description        | TEXT         | 任务描述                                   | 否   | 否   |

| due_date           | DATE         | 截止日期                                   | 否   | 否   |
| status             | ENUM         | 待处理/已完成，默认"待处理"                 | 否   | 否   |

| created_at         | DATETIME     | 创建时间                                   | 否   | 否   |
| updated_at         | DATETIME     | 更新时间                                   | 否   | 否   |

**末级待办联动规则**：
- 当一个待办的所有子待办（parent_id = 该待办ID）状态全部为"已完成"时，该待办自动更新为"已完成"
- 首页和个人待办列表仅展示末级待办（没有子待办的待办，即 NOT EXISTS 子记录）

**SQL建表语句：**
```sql
CREATE TABLE todos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    parent_id INT COMMENT '父待办ID，支持多级树形结构，NULL为顶级',
    title VARCHAR(200) NOT NULL COMMENT '任务标题',
    description TEXT COMMENT '任务描述',
    priority ENUM('高','中','低') DEFAULT '中',
    due_date DATE COMMENT '截止日期',
    status ENUM('待处理','已完成') DEFAULT '待处理',
    assignee_id INT COMMENT '负责人ID',
    creator_id INT COMMENT '创建人ID',
    source_type ENUM('project','wbs','system') DEFAULT 'project',
    source_id INT COMMENT '来源记录ID',
    transferred_from_id INT COMMENT '转办来源人ID（用于转办记录）',
    completed_at DATETIME COMMENT '完成时间',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (parent_id) REFERENCES todos(id) ON DELETE CASCADE,
    FOREIGN KEY (assignee_id) REFERENCES users(id),
    FOREIGN KEY (creator_id) REFERENCES users(id),
    INDEX idx_parent (parent_id),
    INDEX idx_assignee (assignee_id),
    INDEX idx_status (status)
);
```
