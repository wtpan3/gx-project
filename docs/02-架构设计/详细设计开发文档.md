## 〇、使用说明（开发必读）

### 0.1 本文档定位

本文档是**从原型到代码的翻译层**。它把已定稿的 HTML 原型、V2.3 需求文档、三份架构设计文件（全局设计/业务规则说明/数据库设计）整合为可直接开发的规格说明。

**权威边界（开发严格遵守）**：

- **页面交互 + 视觉呈现**（布局、组件长相、点击后的反应、弹窗/表格样式、字段在页面上如何摆放）：以**定稿原型**为唯一真相源，照原型还原。
- **数据模型、字段定义、状态枚举**：以 **V2.3 需求文档 + 数据库设计 V1.2** 为准。
- **业务逻辑（计算规则、联动规则、校验规则、流转条件等）**：**原型中的业务逻辑不作为权威依据**——原型可能写错。业务逻辑一律以 V2.3 需求 + 业务规则说明为准；**凡有疑问、或原型与需求不一致、或需求本身未写清，一律暂缓实现并向项目经理确认，不得擅自按原型或按推测实现。**
- 已发现的冲突/过时点见「附录 A」，已需确认的业务逻辑见「附录 B」，开发按标注执行或先行确认。

## 一、技术栈与工程约定

### 1.1 技术栈（以现有代码为准）

| 层 | 选型 |
|----|------|
| 前端框架 | React + TypeScript |
| UI 组件库 | Ant Design (antd) |
| 后端框架 | FastAPI (Python) |
| 数据库 | MySQL 8.0 |
| ORM | SQLAlchemy |
| 认证 | JWT Bearer Token |
| 图表 | 环形图用 CSS conic-gradient / 甘特图用自定义 table + 绝对定位色条 |

### 1.2 API 通用约定

- 统一前缀：`/api/v1/`
- 认证：请求头 `Authorization: Bearer <token>`；默认账号 `admin/Admin@2026`、`pm001/Admin@2026`
- 返回结构：成功返回业务 JSON，错误返回标准 HTTP 状态码 + `{detail}`
- 列表接口统一支持：分页 `page/page_size`、筛选参数、排序参数
- 全局筛选器参数（建设年份/学校/阶段）与模块内筛选为 **AND 叠加** 关系

### 1.3 工程约定

- 所有金额/数量为整型或定点，不用浮点
- 日期统一 `yyyy-MM-dd`，时间 `yyyy-MM-dd HH:mm:ss`
- 软删除字段 `is_enabled`（1启用/0停用），被引用数据不物理删除
- 所有增删改操作写 `operation_logs`

## 二、全局 UI 规范（所有页面强制遵循）

### 2.1 整体布局

- **左侧固定侧边栏**：宽 220px，深色背景 `#001529`，`position:sticky; top:0; height:100vh; overflow-y:auto`，不随主内容区滚动
- **右侧主区**：`flex:1`，纵向排列 = 顶栏(56px) + 内容滚动区
- **顶栏**：高 56px，白底，`box-shadow:0 1px 4px rgba(0,0,0,.08)`；左侧页面标题，右侧当前用户名 + 头像

- **侧边栏顶部 Logo 文字统一为**：`项目交付管理系统`
- **菜单项顺序（含图标）**：

### 2.3 详情交互统一为居中弹窗（Modal）

- **所有二级下钻详情统一用居中弹窗（Modal），不用右侧抽屉（Drawer）**
- 遮罩：`rgba(0,0,0,.45)`，弹窗居中 `display:flex; align-items:center; justify-content:center`
- 弹窗动画：`transform:scale(.96)→scale(1)` + 淡入
- 宽度：普通详情约 560px，复杂详情（设备/任务）约 720px
- 结构：`modal-hd(标题+×) / modal-bd(内容滚动) / modal-ft(操作按钮)`
- 关闭方式：点 ×、点遮罩、按 ESC、点"关闭"按钮，四种均可

> ⚠️ **命名遗留**：设备信息原型、项目计划原型的 CSS 类名/JS 函数名仍沿用 `drawer`/`openDetail`，但实际 CSS 已是居中缩放模态（已核实）。**开发一律按 Modal 实现，勿被 drawer 命名误导。** 项目计划原型 233-247 行的 `.drawer*` 系列为废弃死代码（但 `.desc-item/.desc-k/.desc-v` 仍被 Modal 使用，保留）。

### 2.4 表格规范（强制）

- `table-layout:fixed` 强制固定布局，每列固定宽度，不允许内容撑开列宽
- 单元格文本：`white-space:nowrap; overflow:hidden; text-overflow:ellipsis`，超长省略号截断
- 悬停显示完整内容：`title` 属性或 Tooltip
- 表格总宽超容器时，外层容器 `overflow-x:auto` 横向滚动，**不压缩列宽、不换行**
- 首页里程碑/风险表：表头与内容**全部居中**

### 2.5 数据下钻规范

| 元素类型 | 触发 | 目标 |
|----------|------|------|
| 仪表板数字卡片 | 点击卡片 | 页面跳转到对应列表页（带筛选参数） |
| 图表节点（环形图扇区/柱子） | 点击 | 页面跳转到筛选列表 |
| 列表行 | 点击行任意区域 | 详情弹窗（Modal） |
| 关联字段（如学校名） | 点击字段值 | 关联对象详情弹窗（Modal） |

- 下钻深度不超过 3 层：仪表板→列表页→详情弹窗
- 悬停下钻元素：鼠标变手型，下划线/背景变化
- 下钻后无数据：显示"暂无数据" + 返回按钮

### 2.6 通用操作规范

- **删除**：二次确认弹窗"确定要删除【记录名】吗？此操作不可恢复"；被引用则提示"该记录已被引用，无法删除"
- **批量操作**（项目计划/设备信息/风险管理列表）：左侧复选框 + 全选；选中后顶部出现批量操作栏（批量更新状态/批量分配责任人/批量删除）；执行前二次确认；结果反馈成功/失败条数
- **列表搜索**：关键词搜索框在左上，高级筛选按钮在右
- **筛选区按钮（全局统一，含原型缺陷修正）**：所有列表页筛选区右侧**必须带「🔍查询」和「🔄重置」两个按钮**，筛选条件选择后点"查询"生效、点"重置"清空。
  > ⚠️ **原型缺陷修正**：设备信息/交付进展/风险管理/系统管理各原型筛选区均有查询/重置按钮，**唯独项目计划原型 V2.2 的 `filter-toolbar` 漏了这两个按钮**（做成了即时筛选）。此为原型疏漏，开发时项目计划筛选区**须补上查询/重置按钮**，与其他模块统一，不照抄原型的无按钮设计。
- **导出**：可选 Excel(.xlsx，正式报告) 或 CSV（数据分析），导出当前筛选条件下全部数据（不分页）

## 5.6 业务规则与联动

  - 学校完成率 = 已验收学校数/总学校数
  - 硬件完成率 = 运行中设备数/总设备数
  - 软件完成率 = Σ各模块进度/模块数
- **首页健康度**（状态判断）：
  - 🟢正常：无延期>7天任务 且 无待处理风险 且 进度≥计划80%
  - 🟡关注：存在延期3-7天任务 或 存在待处理风险 或 进度<计划80%
  - 🔴异常：存在延期>7天任务 或 ≥2个待处理风险 或 进度严重滞后
- 里程碑延期判断：当前日期超过计划完成日期且状态≠已完成 → 自动"已延期"（每日定时检查）
- 末级待办联动：下级全部完成 → 上级自动"已完成"；首页仅展示末级待办

## 6.7 业务规则与联动

### 6.7.1 父子任务状态联动
1. **单一数据源**：同一任务在首页里程碑/项目计划页/交付进展页三处展示，任一处维护全局同步，全局只有一个状态
2. 子任务变"进行中" → 所有祖先父任务自动"进行中"（若原为待开始）
3. 某父任务全部直接子任务"已完成" → 该父任务自动"已完成"（逐级向上传导）
4. 某父任务全部直接子任务"待开始" → 父任务"待开始"
5. **父任务不可越级完成**：有未完成子任务时，系统禁止手动改父任务为"已完成"，提示"该任务还有 N 个子任务未完成…"

### 6.7.2 状态流转
`待开始 → 进行中 → 已完成(材料齐全)`；`→ 待补材料(材料缺失) → 上传后 → 已完成`；`→ 已延期(超时)`

**列表列**：建设年份 / 项目名称 / 模块 / 系统名称 / 设备名称 / 产线 / 品牌 / 型号 / 设备类型 / 采购类型 / 单位 / 计划数量 / 已录入 / 操作
> "已录入"列显示设备信息中该字典项已录入数量之和。

## 12.4 交互规则

- 筛选：按项目/系统/建设年份 + 查询/重置
- 新增/编辑/删除（软删除）
- 批量导入（Excel）
- 设备名称下拉模糊搜索
- 被引用字典项：删除按钮置灰（软删除）

## 12.5 业务规则

- **唯一性**：项目名称 + 系统名称 + 设备名称 + 建设年份 四者组合唯一
- **层级**：模块 → 系统 → 设备 三级
- **主数据 vs 台账**：本表是主数据(可增删改)，设备信息是业务台账(不可增删)
- 建设年份默认2026；2027及以后的设备**仅在设备字典录入**，设备信息模块不可录入
- 被设备信息引用的字典项不可物理删除（软删除 is_enabled=0）
- **计划vs实际**：设备信息各批次已交付数量之和超过计划数量 → 橙色警告(⚠)不阻止保存，由PM判断

## 12.6 数据来源与 API

- 列表：`GET /api/v1/device-systems`（筛选 project/system/year）
- 增删改：POST/PUT/DELETE `/api/v1/device-systems`
- 设备录入时读取此表复制规格快照到 devices
