## 🔍 待办5的意外收获

### 发现的真实问题

运行schema检查脚本时，发现wbs_tasks表存在数据不一致：
- **数据库**：有`source_device_id`列（INT，关联devices.id）
- **Model**：`WbsTask`类缺失该字段
- **文档**：数据库设计文档§2.9明确定义了该字段（"来源设备记录ID"）

### 根因

这是典型的"ddl.sql与models.py独立演化"问题：
- 建表DDL中包含该字段
- 但后续Model代码编写时遗漏了
- 两者未同步检查，导致长期不一致

### 修复

在`backend/app/models/wbs_task.py`第32行补上：
```python
source_device_id = Column(Integer, ForeignKey('devices.id'), nullable=True)
```

### 验证

再次运行检查脚本，结果：
```
检查表数: 8
发现问题: 0
✓ 所有表结构一致
```

**影响评估**：
- 该字段当前未被使用（设备→WBS自动生成逻辑尚未开发）
- 补上字段后，未来开发该功能时能正常访问

## 📝 脚本使用示例

### SQL导入脚本

```bash
# Bash (Git Bash / WSL)
cd backend
./scripts/import_sql.sh ddl.sql                    # 导入到gx_project_dev
./scripts/import_sql.sh migration.sql gx_project   # 导入到指定库

# PowerShell
cd backend
.\scripts\import_sql.ps1 ddl.sql
.\scripts\import_sql.ps1 migration.sql gx_project
```
