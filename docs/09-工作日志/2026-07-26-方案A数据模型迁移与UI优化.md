### 一、数据模型迁移（方案A）

**目标**：支持"选父任务→层级自动确定"的新增方式，进度可独立编辑

**实施内容**：
1. **数据库迁移**（`add_parent_progress_columns.py`）
   - ALTER TABLE wbs_tasks 加两列：
     - `parent_id INT NULL` + 外键（自关联 wbs_tasks.id）
     - `progress INT NOT NULL DEFAULT 0`（0-100）
   - 回填现有 36 条数据：
     - progress 按状态映射（已完成100/进行中50/待补材料60/已延期40/待开始0），成功回填 25 条
     - parent_id 按路径前缀匹配（现有数据为平行结构，回填 0 条）

2. **后端接口重构**（`backend/app/api/v1/project_plan.py`）
   - **create_task 重写**：
     - 接受 `task_name`（本级名）+ `parent_id`（可选）+ `progress`
     - 据父任务自动推导 L1-L4 字段和层级（子层级 = 父层级 + 1）
     - task_code 自动生成 `WBS-AUTO-{序号}`（`_gen_task_code` 函数）
     - 继承父任务的 construction_year
   - **新增接口**：`GET /project-plan/parent-options`
     - 返回 L1-L4 任务列表（L5 不能作父）
     - label 格式：`"L1 / L2 / L3 (L3)"`，带完整路径+层级
   - **list/gantt/detail 接口**：响应 dict 补充 `progress` 和 `parent_id` 字段

3. **前端模型同步**（`frontend/src/pages/ProjectPlan/index.tsx`）
   - TaskItem 接口加 `progress?: number` 和 `parent_id?: number`
   - 所有视图（甘特图/列表/看板）改用真实 progress 字段，回退到状态映射

## 💡 技术备注

### Python import 缓存问题
- Windows 下 uvicorn --reload 文件监听**不可靠**
- 建议开发时手动重启（Ctrl+C → 重新运行），不依赖热重载
- 或用 `watchdog` 等第三方工具替代 uvicorn 内置监听

### 前端筛选框"全部"选项
- 数字型 Select 不能用 `value={undefined}`（React 警告）
- 哨兵值方案：`'__ALL__'` 字符串，onChange 时转 `undefined`
- Option value 统一字符串化避免类型混合

### parent_id 回填 0 条的说明
- 现有 36 条数据是**平行导入的测试数据**（每条 L1-L4 路径独立）
- 没有"某任务是另一任务的子级"的结构关系
- 新建任务时选父任务会建立正确的 parent_id 关联
