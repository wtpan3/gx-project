## 变更列表

### 2026-07-28：多项目隔离机制

**类型**：架构 + 数据库

**原因**：系统需要支持同时管理多个独立项目，切换项目后全系统数据自动切换。

**内容**：
- 12张核心表新增 `project_id INT` 字段，外键关联 `project_info(id)`
- 影响的表：schools, dict_items, wbs_tasks, devices, trainings, risks, reports, files, operation_logs, templates, software_modules, production_lines
- 不设 `project_id` 的表：users, suppliers, project_info, task_attachments, template_wbs_stages
- 新建 `systems` 表，建立 产线→系统→设备 三级层级
- 现有数据统一回填 `project_id=1`（默认项目）

**关联文档**：数据库设计.md, 需求文档V2.3


### 2026-07-28：模板管理架构重构

**类型**：架构 + 数据库

**原因**：原模板管理仅支持单阶段关联（`stage` ENUM），无法支持一个模板关联多个WBS层级，也无法实现材料卡点机制。

**内容**：
- `templates` 表从10个字段扩展到18个字段
- 删除 `stage` 字段，新建 `template_wbs_stages` 关联表
- `type` 从 ENUM 改为 VARCHAR(50)，从数据字典读取
- 新增版本管理机制：`template_key` 分组 + `is_latest` 标记
- 新增文件元信息：`file_name`, `file_size`, `file_type`, `upload_by`, `download_count`

**关联文档**：数据库设计.md, 需求文档V2.3


### 2026-07-28：材料卡点机制

**类型**：功能 + 数据库

**原因**：任务完成时需校验佐证材料是否已上传，确保交付质量。

**内容**：
- `wbs_tasks` 表新增 `requires_material` + `material_status`
- `files` 表新增 `wbs_task_id` + `template_id`
- 业务规则：`requires_material=1` 且 `material_status≠已完成` 时，任务禁止标记为"已完成"

**关联文档**：数据库设计.md, 需求文档V2.3


### 2026-07-28：数据字典扩充

**类型**：数据库

**原因**：模板类型需要从数据字典读取，支持交付材料类和汇报材料类共12种类型。

**内容**：
- 新增 `模板类型` 分类（12条）：到货验收表、加电测试表、校级验收单、培训确认表、培训签到表、培训反馈表、其他交付材料、项目周报、项目月报、校级周报、校级月报、专项汇报
- 废弃 `关联阶段` 分类（5条），改用 `template_wbs_stages` 表动态关联

**关联文档**：数据库设计.md


### 2026-07-28：删除设备字典表（device_systems）

**类型**：数据库

**原因**：设备规格管理功能合并至设备信息模块，不再维护独立字典表。

**内容**：
- 删除 `device_systems` 表
- 设备规格（品牌/型号/参数/类型/单位）直接在 `devices` 表中维护
- 通过 `system_name`/`device_name` 去重查询实现字典效果

**关联文档**：数据库设计.md, 需求文档V2.3, 详细设计开发文档.md


### 2026-07-28：产线系统层级建立

**类型**：架构 + 数据库

**原因**：原系统中"系统"仅为 `devices.system_name` 文本，无法表达"系统归属哪条产线"，导致按产线筛选设备无数据支撑。

**内容**：
- 新建 `systems` 表（21条），通过 `production_line_id` 关联 `production_lines`
- 现有9条真实产品线：PL-CLASSROOM, PL-DAXUEQING, PL-PLATFORM, PL-STEAM, PL-EXAM-LANG, PL-SPORT, PL-MENTAL, PL-SCIPOP, PL-READING
- 层级链路：产线 → 系统 → 设备
- 828条设备已回填 `system_id`，412条为NULL待补充

**关联文档**：数据库设计.md, 需求文档V2.3, README.md


### 2026-07-26：整体进度算法简化

**类型**：业务规则

**原因**：原加权算法（学校30% + 硬件40% + 软件30%）在实际使用中难以准确反映真实进度，且权重配置复杂。

**内容**：
- 旧算法 → 新算法：已完成末级任务数 / 总末级任务数（无加权）
- 末级判定：`work_content_l4` 非空的任务
- 同时废弃首页健康度扣分制

**关联文档**：业务规则说明.md, README.md


### 2026-07-25：风险管理简化模型

**类型**：业务规则

**原因**：完整重量级模型（概率×影响矩阵）在中小型教育信息化项目中维护成本高、使用率低。

**内容**：
- **保留**：风险等级（高/中/低，手工评定）
- **删除**：概率、影响（原矩阵下拉）、风险等级自动计算、关联应对任务（risk_tasks）、应对计划完成时间
- 新增 `progress_note` 字段，支持自由文本进展说明
- 状态：待处理 / 处理中 / 已关闭

**关联文档**：业务规则说明.md, 需求文档V2.3, 详细设计开发文档.md


### 2026-07-25：学校看板与培训管理整合

**类型**：功能

**原因**：学校看板和培训管理功能与交付进展高度重叠，独立模块增加导航复杂度。

**内容**：
- 学校看板 → 合并至交付进展第二层（单校全景详情）
- 培训管理 → 合并至交付进展第一层（项目整体培训情况）
- 两个模块不再作为独立一级菜单

**关联文档**：全局设计.md, README.md, 需求文档V2.3


### 2026-07-22：MySQL中文双重编码修复

**类型**：数据库

**原因**：导入SQL时未指定字符集，导致ENUM中文值被双重编码。

**内容**：
- 修复表：software_modules.phase, todos.priority, todos.status
- 预防措施：强制使用封装脚本 `import_sql.ps1` / `import_sql.sh` 导入，自动加 `--default-character-set=utf8mb4`

**关联文档**：README.md（踩坑记录）, CLAUDE.md（MySQL规范）

**内容**：
